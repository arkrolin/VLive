# Live2D 方案 V5：数据缩放律实测 —— 扩充数据集到底能不能改善

> 起因：用户观察到"数据集虽然动作质量高，但来自同一来源导致动作资产数较少，共享先验也少"，
> 问进一步扩充数据集是否有帮助。
>
> 本文用五组实验回答。**结论是：能，但幅度远小于直觉，而且瓶颈根本不在这里。**
> 更重要的是，实验推翻了"同一来源导致先验少"这个前提本身。

---

## 0. 一句话结论

| 问题 | 答案 |
|---|---|
| 随机爬更多模型有用吗？ | **几乎没用**。角色数 ×100 → 先验增益 13.3% → 17.4% |
| 有更好的扩法吗？ | 有。等预算下 FOCUS(20.7%) > DEEPEN(18.2%) > WIDEN(14.1%) |
| 天花板在哪？ | **每个动作 8 个角色**就饱和，再多完全无效 |
| 是"来源单一"的问题吗？ | **不是**。语料 schema 中位 Jaccard 仅 0.071，已经很分散 |
| 真正的瓶颈是什么？ | **部署侧目标 rig 的参考动作数**，不是训练数据 |

---

## 1. 缩放律：加角色几乎没有收益

留一角色，`act(a)` 只用 N 个训练角色估计，其余不变。评测集固定，没有先验时回退到 rig-only。

### L2 振幅签名

| 训练角色数 | R² | 相对 rig-only 增益 | 先验覆盖率 |
|---:|---:|---:|---:|
| 2 | 0.371 | 7.5% | 44.6% |
| 4 | 0.350 | 9.7% | 55.5% |
| 8 | 0.343 | 15.2% | 78.2% |
| 16 | 0.352 | 17.2% | 92.0% |
| 24 | 0.356 | 18.4% | 97.4% |
| 28 | 0.361 | 19.5% | 100.0% |
| *(rig only)* | *0.290* | *0%* | — |

**关键在于最后一列。** R² 从 0.371 到 0.361 是**下降**的；所有表观增益都来自**覆盖率**（从 44.6% 到 100%）。
一旦每个动作都有先验可用，再加角色就完全不动了。

L1 通道激活同理：R² 0.227 → 0.270，覆盖率 44.6% → 100%。

---

## 2. 为什么会饱和：Heaps 定律 b = 0.82

```
distinct actions after N characters:
  N=1:59  N=2:112  N=4:201  N=8:379  N=16:629  N=35:1189
  fit  V(N) = 64.6 * N^0.82
```

新角色带来的主要是**新动作名**，不是给已有动作补样本。

由此可以推出支持深度的增长率：

```
支持深度 = 总资产 / 动作名数 ∝ (24·N) / (64.6·N^0.82) ∝ N^0.18
```

**角色数翻 11 倍，每个动作的支持深度只涨 1.5 倍。** 这就是缩放曲线平掉的数学原因。

当前实况：1189 个动作名，**中位支持 = 1 个角色**，只有 2.9% 的动作名有 ≥9 个角色覆盖。

---

## 3. 饱和点实测：8 个角色到顶（混淆项已排除）

"支持角色多的动作增益高"有一个致命混淆——那些动作可能本来就更套路化。
所以固定 **17 个有 ≥12 角色支持的动作**，只改变允许使用的供体角色数：

| 允许使用的供体角色数 | 先验增益 | n |
|---:|---:|---:|
| 1 | 5.4% | 655 |
| 2 | 13.7% | 655 |
| 4 | 17.0% | 655 |
| 8 | 18.9% | 655 |
| 11 | 19.6% | 655 |
| 全部 | **19.8%** | 655 |

同一批动作、同一批评测点，只变深度。**混淆排除，效应是真的，但 8 个就到顶。**

---

## 4. 供体选择完全无效 —— 机制是均值消噪，不是"找像的老师"

中途出现过一个诱人的中间结果：按 rig schema 相似度分层，供体越像增益越高
（schema-far 0.3% / schema-mid 4.8% / schema-near 8.1%，看起来是 27 倍差距）。

**但那是单供体测量。** 头对头一比就塌了：

| 供体选择策略 | 先验增益 |
|---|---:|
| 均匀平均所有供体（当前做法） | **19.2%** |
| 按 schema 相似度² 加权 | 19.2% |
| 只取 schema 最像的 1 个 | 7.2% |
| 只取 schema 最像的 3 个 | 16.7% |
| 只取 schema 最像的 5 个 | 18.4% |

换成**行为相似度**（角色整体动作统计的余弦，这是加性模型学不到、神经网络才能学的交互项）：

| 供体选择策略 | 先验增益 |
|---|---:|
| 均匀平均（基线） | **19.2%** |
| 按行为相似度³ 加权 | 14.1% |
| 行为最像的 5 个 | 18.2% |
| **行为最不像的 5 个（对照）** | **17.3%** |

最像的 5 个 vs 最不像的 5 个，差距只有 **0.9 个百分点**——噪声水平。

> **结论：供体的身份不携带信息，只有供体的数量携带信息。**
> 跨角色先验本质是一个均值估计问题，而均值估计在 ~8 个样本就收敛。
> 这解释了前面所有饱和现象，也意味着任何"检索相似角色"的架构设计都是白费力气。

这条同时**推翻了用户的前提假设**：不是"来源单一导致先验少"。
语料的 rig schema 两两 Jaccard 中位数仅 **0.071**（p10 0.038 / p90 0.172），已经相当分散；
而且就算分散，也不影响先验质量，因为质量只取决于平均了几个供体。

## 5. 等预算三种扩法头对头

固定 600 个训练资产的预算，留出的评测角色不变：

| 策略 | 先验增益 |
|---|---:|
| WIDEN　每个角色薄薄取一层 | 14.1% |
| DEEPEN 只取 12 个角色，每个取很多 | 18.2% |
| **FOCUS　固定 40 个动作清单，跨所有角色** | **20.7%** |

**定向收集比随机爬多 47% 的相对收益，成本一样。**

### 换算成实际扩充计划

当前全语料加权平均先验增益 = **13.3%**（因为 36.0% 的资产其动作只有 1 个角色演过）。

随机扩充：

| 角色数 | 支持深度 | 加权先验增益 |
|---:|---:|---:|
| ×2 | ×1.13 | 13.3% → 13.9% (+4.3%) |
| ×10 | ×1.51 | 13.3% → 15.4% (+15.4%) |
| ×100 | ×2.29 | 13.3% → **17.4%** (+30.4%) |

定向扩充（把 top-K 动作各补到 8 个角色）：

| 覆盖动作数 | 占资产比 | 需新增资产 | 加权先验增益 |
|---:|---:|---:|---:|
| top-80 | 49.7% | ~189 | 13.3% → 13.6% |
| top-160 | 62.3% | ~625 | 13.3% → **14.5%** |

**注意：即使把角色数扩到 100 倍，也只是逼近 19.8% 这个饱和值。**

## 6. 方差分解：天花板是画师分歧，不是数据量

| 成分 | 占总方差 |
|---|---:|
| 由 rig 身份解释 | 23.3% |
| 由动作标签解释 | 36.0% |
| **同角色同动作内部残差（不可约噪声）** | **24.2%** |

即使有一张完美的 (rig × action) 查找表，也还剩 24.2% 解释不了——**那是同一个画师对同一个动作的两次不同演绎**。

上界对照（L2 振幅）：

```
rig-only                     R² 0.290
+ 当前跨角色先验              R² 0.361
+ 无限完美的跨角色数据（推算） R² ~0.39     <- 数据量的极限
同角色 oracle                R² 0.671     <- 真正的目标
```

**扩数据最多能走完 0.29 → 0.39 这一段，剩下的 0.28 是数据量买不到的。**

---

## 7. 真正的瓶颈：部署侧的参考动作数

同一组实验里，改变**目标 rig 上可用的参考动作数** k：

| k（目标角色的参考动作数） | R² rig-only | R² rig+先验 |
|---:|---:|---:|
| 1 | −0.548 | −0.391 |
| 2 | −0.170 | −0.012 |
| 4 | 0.024 | 0.178 |
| 8 | 0.117 | 0.272 |
| 16 | 0.164 | 0.319 |
| 全部 | 0.207 | 0.361 |

**k=1 时 R² 是负的——比直接输出全局平均还差。**

这条曲线的动态范围（−0.55 → 0.36，跨度 0.91）比整个数据扩充能带来的（0.29 → 0.39，跨度 0.10）**大九倍**。

> 换句话说：与其花三个月爬 10 倍的模型，不如确保产品设计里**目标角色至少有 8 条已有动画可参考**。

这也是一条硬性产品约束，需要写进需求：**参考视频不能只给一条。**

---

## 8. 那 0.28 的缺口从哪来

V4 已经给出了方向，V5 的数据进一步坐实了它：

- V4 发现：**手势语素可迁移（`motouweixiao` +0.96），纯情绪词不可迁移（`weixiao` +0.01），6/6 配对全为正，平均 delta +0.55**
- V5 发现：Live2D 语料的跨角色信息量在 8 个供体就榨干了

两条合起来指向同一个结论：**可迁移的成分是"手放在哪"这种空间信息，而 Live2D 语料能提供的空间信息量已经到顶了。**

而"手放在哪"恰恰是**人体视频 / 姿态估计数据**能海量提供的东西，且量级比任何 Live2D 语料大好几个数量级。

所以扩数据的正确方向不是"爬更多 Live2D 模型"，而是**换模态**：

| 方向 | 提供什么 | 量级 |
|---|---|---|
| 更多 Live2D 模型 | 已饱和的跨角色均值 | 无意义 |
| 人体视频 / 2D 姿态 | 手/头/躯干的空间轨迹 | 10³~10⁵ 倍 |
| 目标 rig 的更多参考动画 | rig 项（真正的大头） | 直接决定成败 |

---

## 9. 需要你决策的两件事

### 9.1 参考输入的定义（上一轮提过，现在有更强的数据支撑）

现在设定是"参考视频 = 同角色已有 Live2D 动画"，它只提供 rig 信息、不提供编舞信息。
§7 的表说明这个输入**至少要 8 条**才能让模型跑在正收益区间。

两个选项：

- **A. 维持现状**：要求目标角色至少提供 8 条已有动画。简单，但限制了"全新角色零素材"的场景。
- **B. 允许第二路输入描述目标动作**（真人视频/别的角色动画/随手拍）。
  这样 §8 的 0.28 缺口就由这一路输入补上，而不是指望语料。
  不违反你"输出不需要人工二次编辑"的要求。

### 9.2 如果仍要扩充 Live2D 语料

不要随机爬。按 §5：**先定一份动作清单，然后针对性凑齐每个动作 8 个角色**。
top-160 动作补齐只需新增约 625 个资产，比随机爬 10 倍模型（约 33000 个资产）效果还好。
