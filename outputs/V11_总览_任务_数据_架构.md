## 1. 任务定义

### 1.1 形式化

```
输入：  角色 m（其 .moc3 + 该角色其它动作的曲线）
        动作名 a（如 "IDLE" / "SMILE" / "shihao"）
输出：  曲线张量  X ∈ R^(P × T)
        P = 该动作驱动的参数个数（实测：中位 68，范围 8–202）
        T = 48 帧
        X[p, t] ∈ R  是第 p 个参数在第 t 帧的原始数值（Live2D 参数单位）
```

**约束**：只生成「生成目标参数」——由 `gen_mask` 排除物理演算 / 眨眼 / 口型同步 / 非动作参数。
`P` 因样本而异，在 batch 里 padding 到 `max_tokens=128`，用 `token_mask` 屏蔽。

### 1.2 为什么这个任务不容易

`exem(action, param)` = **跨所有角色的同（动作，参数）均值曲线**。
这是一个「作弊式」的强基线：光靠它，`abs_mae` 就已是 **1.5196**（全量 614）。

⇒ 所以本项目的**一切比较都相对 `exem`**。「+48.2%」= 比「直接输出跨角色平均曲线」好 48.2%。
⇒ 危险在于：**`abs_mae` 很容易继续降，而曲线形状毫无改善**（§6.3）。

### 1.3 评测协议

| 项 | 设定 |
|---|---|
| 验证集 | **34 个 pinned 角色**（`outputs/val_holdout_all.json`），全角色 holdout |
| 验证样本 | **614 个（角色，动作）实例** |
| 样本过滤 | ⭐ 只保留**被 ≥5 个角色共有**的动作（`eval_shared_min_models=5`） |
| 参数量 | 37546 个 (实例, 参数) 槽位；其中**常数通道 43.2%**、动通道 56.8% |
| 主口径 | `eval_ckpt.py` 全量 614 的 **`abs_mae`**（原始单位、跨方案可比） |
| 形状口径 | `diag_shape.py` / `diag_shape_floor.py` 的三项 + 保留率 |
| 任务语义 | 「**已知动作，新角色**」（部署场景；目标动作在部署时不存在） |

### 2.6 归一化与先验

```python
span = (hi - lo).clamp(min=max(g_hi-g_lo, 1.0) * 0.02)   # 近常数参数下限保护
x0   = ((target - lo) / span).clamp(-0.5, 1.5)           # 逐参数按量程归一
exem_s = ((exem - lo) / span).clamp(-0.5, 1.5)
```

- `lo / hi` 来自 `range_cache_580_all_v9all_12083.pkl`（全语料扫描的逐参数量程）。

## 3. 模型架构设计

### 3.1 总览

```
                    ┌──────────────── 条件（全部加性叠到 token 上）────────────────┐
                    │ 参数名  ParamNameEncoder        (n_i, d)                     │
                    │ 角色   identity_enc(rig 96d)    (1, d)   ← rig_loo: 排除目标动作 │
                    │ 动作   action_emb(action_id)    (1, d)                       │
                    │ 角色统计 char_stats_enc(5d)     (n, d)                       │
                    │ 检索   bank_attn → att_emb      (n, d)                       │
                    └──────────────────────────────────────────────────────────────┘
                                            ↓  加性合并
输入三通道                        tok (B, n, d)
 ┌─ x_t      (B,n,T)  加噪/零
 ├─ exem     (B,n,T)  跨角色动作均值 ──→ in_proj: Linear(C→d) ──→ h (B,n,T,d)
 └─ bank_att (B,n,T)  该角色其它动作检索                                   │
                                            ↓
                        ┌────────── 6 × TemporalBlock ──────────┐
                        │ 在 T 轴上做注意力，AdaLN(tok + 时间步)  │   ← "stable DiT"
                        │ QKNorm · RMSNorm · SwiGLU · 零初始化 AdaLN│
                        └───────────────────────────────────────┘
                                            ↓
                        ┌────────── 6 × TokenMixBlock ──────────┐
                        │ 在 P 轴上做注意力（token_mask 屏蔽 padding）│
                        └───────────────────────────────────────┘
                                            ↓  h (B,n,T,d)
                                       输出头（两种，见 3.4）
                                            ↓
                                    x0_hat (B,n,T) ⊙ token_mask
```

### 3.2 主干：参数即 token 的双轴 Transformer

| 项 | 值 |
|---|---|
| `d_model` | **384** |
| 层数 | **6**（Temporal 与 TokenMix 各 6） |
| 注意力头数 | 8 |
| `mlp_ratio` | 4（SwiGLU 式三层 MLP） |
| dropout | 0.1 |
| 归一化 | **RMSNorm**（非 LayerNorm）+ **QKNorm**（对 q/k 单独归一） |
| 调制 | **AdaLN**，条件 = `tok + 时间步嵌入`，**AdaLN 全零初始化** ⇒ 初始时每个 block 是恒等映射 |

**为什么要两个轴**：
- T 轴（Temporal）：让每一帧看到整条时间序列 —— 形状信息在这里。
- P 轴（TokenMix）：让参数之间互相看（如左右手/左右臂共享风格）—— 参数间一致性在这里。

**设计来源**：RDT 论文的 "stable DiT" 补丁（QKNorm + RMSNorm + SwiGLU + 零初始化 AdaLN）。

### 3.3 条件注入：五条通路

| # | 通路 | 维度 | 内容 | 状态 |
|---|---|---|---|---|
| 1 | `ParamNameEncoder` | d | 参数名的词级编码，带 `name_dropout=0.2` | 基础 |
| 2 | `identity_enc(rig)` | d | **96d 静态角色签名** = 方差最大的 48 个参数的 z-score（量程，均值） | ✅ 有效 |
| 3 | `action_emb` | d | 动作 id 查表 | ✅ 有效（优于名字编码） |
| 4 | `char_stats_enc` | d | 5d：rest 值 / 典型幅度 / lo / hi / log1p(支持数) | ❌ **实测是死的**（§3.5） |
| 5 | `bank_attn` | d | 该角色**其它动作**的 K=8 条曲线，**逐参数**交叉注意力 | ⭐ **唯一的信息源** |

⭐ **`rig_loo`（必须开）**：
原始 96d rig 把**目标动作本身**也统计进去了 ⇒ **泄漏目标幅度**。
实测：29.2% 的通道里目标动作贡献了 ≥50% 的全局量程，5.2% 是唯一贡献者。
后果：point MAE 提升 +39.8%，但**形状（一阶差分）只提升 +2.1%** —— 因为泄漏的是「幅度」。
`rig_loo=True` 用「次小/次大值」精确扣除目标动作的贡献，与部署形态一致。

⭐ **`bank_attn` 为什么必须「注意力」而不是「平均」**（oracle 实测）：

| 候选池 | 逐参数选择（oracle） | 直接平均 |
|---|---|---|
| 跨角色的同动作曲线 | 1.7673 | **1.6242**（平均更好） |
| **本角色的其它动作曲线** | **0.5031** | 1.8510（平均差 3.7 倍） |

⇒ 跨角色时候选是噪声，要平均；**本角色内候选是不同动作，必须「选」**。
所以 bank 只能被 attend over，**绝不能池化**。

### 3.4 输出头：项目当前真正的关键

#### (a) `dense`（旧，V11b 及之前）

```python
out = self.head(h)                    # Linear(d,1) → 整张 (B,n,T) 残差
x0_hat = exem + g * out               # g = 可学习门控（按参数名）
```

- **表达能力天花板 = corr 1.0**（能表示任意曲线）。
- 实测 corr **0.5797** ⇒ **不是容量不足，是归纳偏置/优化问题**。

#### (b) `structured`（当前 SOTA，V11e 起）

```python
h_pool = h.mean(dim=2)                        # (B,n,d)  ← ⚠️ 把 T 轴压掉了
alpha  = self.gain_head(h_pool)               # (B,n,1)  per-param 幅度增益
coef   = self.coef_head(h_pool)               # (B,n,r)  低秩形状系数
basis  = DCT-II 前 r 个模态                   # (r,T)    固定 buffer，非参数
x0_hat = exem * (1 + alpha) + coef @ basis
```

⭐ **设计意图 = 幅度与形状显式解耦**（源自 VoxCPM「规划与渲染必须在架构上分工」的结论）：
- `alpha` 只管**幅度**（乘性增益 α∈R^P）
- `coef @ basis` 只管**形状**（r 维低通基）
- 输出维度从 `P×T ≈ 2688` 塌缩到 `P×(1+r) = 56×9 = 504`

⭐ **全部零初始化** ⇒ 起步**逐位等于** `x0_hat = exem`，所以任何新臂都与基线从同一点出发。

⭐ **DCT 低通基 = 先验（不是容量）**：把每条通道的曲线限制在 r 维低通子空间。
这是**唯一被证明有效的「结构」改动**（corr 0.5797 → 0.7124，**+22.9%**），
同时也消掉了 dense 头的 2× 抖动。

⚠️ **已实现但被否证的开关**：
- `--head_additive_amp`：加性幅度项。**净负**（B1b vs B2 单变量四项全胜）。
  机制：它输出的常向量 ≡ **DCT 第 0 模态**，与 `coef[:,0]@basis[0]` **线性冗余** ⇒ 表达能力 +0、优化难度 +1。
- `--shape_motion_mask`：把形状项只算在动通道上。**不是节省而是重加权**（等效 λ×1.76），
  单独打开会造成「压平陷阱」（→ §6.3）。

### 3.5 生成范式：扩散 vs 回归

| 项 | 设定 |
|---|---|
| 当前 SOTA | **`gen_mode=regress`** —— 确定性残差回归，无噪声，`t=0`，`x_t=0` |
| 备选 | `ddpm` —— DDPM 1000 步余弦调度，`x0`-prediction |
| 结论 | **扩散是净负收益**（exem 先验太强，从纯噪声出发反而破坏了它） |

### 3.6 参数预算（41.378 M）

| 模块 | 参数 | 占比 |
|---|---|---|
| `temporal`（T 轴主干） | 28.360 M | 68.5% |
| `tok_mix`（P 轴主干） | 10.647 M | 25.7% |
| `time_emb` / `action_emb` / `identity_enc` | 2.07 M | 5.0% |
| `bank_q` + `name_enc` + `bank_curve_enc` + `char_stats_enc` | 0.296 M | 0.7% |
| **`gain_head` + `coef_head`（输出头）** | **3,465** | **0.008%** |
| `basis` | (8,48) **固定 buffer**，不占参数 | — |

⭐ **拿下 SOTA 的那个头只占万分之八** ⇒ 「加参数」在这个瓶颈上不是杠杆。

## 4. 训练目标

```python
loss =  电平项                                        # 逐帧电平误差
      + shape_w × 形状项                              # 一阶差分误差（λ = 20）

# 电平项
se    = (x0_hat - x0) ** 2
valid = token_mask ⊙ arm_w ⊙ (span / span_batch_mean) ** span_w    # span_w=1, cap=8
loss_level = (se * valid).sum() / valid.sum()

# 形状项
d_hat = x0_hat[...,1:] - x0_hat[...,:-1]
d_tgt = x0[...,1:]   - x0[...,:-1]
sd    = (d_hat - d_tgt) ** 2
loss_shape = (sd * valid).sum() / valid.sum()
```

| 超参 | 值 | 为什么 |
|---|---|---|
| `span_w` | **1** | 按量程加权。`span_w=2` 等价于原始单位 MSE（= 直接优化 `abs_mae`）。**历史第二大收益** |
| `span_w_cap` | 8 | 防止少数极端量程参数垄断梯度 |
| `shape_w` | **20** | ⭐ λ 已标定：λ=1 时形状项只占 **1.19%**，文档早先建议的 0.1/0.5/1.0 **全是废跑**；λ≈21/42 才到 25%/50%。**λ=20 已饱和，勿再扫 >50** |
| `lr / warmup / wd / clip` | 2e-4 / 3ep / 1e-2 / 1.0 | 标准配方 |
| 调度 | 余弦，`lr_min=2e-5` | |
| `select_metric` | **`abs`** | ⚠️ 不能用 `val_loss` 选 ckpt（实测差 20%） |

### ⭐⭐ 全局 batch 是硬约束：4 卡 × BS 6 = 24

```python
ref = span_t[token_mask > 0.5].mean()     # 逐 rank 的 batch 均值
```

⇒ **span 权重依赖「每个 rank 的 batch 均值」** ⇒ **改 BS 就改了损失尺度** ⇒ 与历史臂不可比。
⇒ 所以 **BS 必须 6、必须 4 卡（不能 2 卡 × BS 12 省卡）** ⇒ **一臂独占 4 卡 ⇒ 多臂只能串行排队**。

### 6.2 四个致命陷阱

| # | 陷阱 | 实测量级 |
|---|---|---|
| 1 | **训练期 val 的 `abs` 完全不可靠** | 水平差 **1.43×**；斜率低估 **~1.8×**；**连排序都会翻转**（同一臂 ep38 落后 1.9% → ep49 领先 6.9%）⇒ **只用于巡检崩坏** |
| 2 | **中途点不可裁决** | 曾据 ep38 得出「加性项损害常数通道」，ep49 同期口径**两处反号** |
| 3 | **`abs_mae` 涨 ≠ 形状对**（正交） | R→V11a→V11b：point 一路涨，**动通道 delta MAE 反而变差**。根因＝损失里本来没有形状项 |
| 4 | **`shape corr` 是「逐实例相关系数的均值」** | 同一 pkl：池化 **0.8809** vs 均值 **0.7124**（差 0.17）；分布**双峰**（26% >0.9、7.1% <0.25、2.1% <0）⇒ **只报均值会掩盖两极** |

### 6.3 「压平陷阱」——为什么必须同时看保留率

`delta MAE` 低的模型可能只是**输出更平的曲线**（平线的 delta MAE 也小）。

| 臂 | dMAE｜动通道 | 幅度保留率 \|Δpred\|/\|Δtgt\| | shape corr | 判定 |
|---|---|---|---|---|
| 平线 | 0 (floor=0.3212) | 0 | — | 无意义 |
| **C1a** | 0.2053（最好） | **76.6%** | 0.5897 | ❌ 压平 |
| **B1b** | 0.2083 | **91.8%** | **0.7124** | ✅ 真形状 |

⇒ **必须四项一起看**：point MAE / shape corr / delta MAE｜动通道 / 幅度保留率。

### 6.4 验收闸（4 条）

1. `abs_mae` 优于 exem 先验 **≥10%**
2. `val_rel_mae_f ≤ 0.05`
3. `train_loss ≤ 0.09` —— ⚠️ 含形状项的臂**天然 FAIL**（λ 计入），**不是回归**
4. **`delta MAE｜动通道 < exem 先验`** —— ⚠️ **前任 SOTA `V11b` 过不了这一条**

## 7. 当前结论与瓶颈

### 7.1 已锁定的结论

| 问题 | 结论 | 证据强度 |
|---|---|---|
| structured 头有用吗？ | ✅ **唯一真正有效的结构改动**（corr +22.9%） | 实测（单变量：vs dense 头） |
| 加性幅度项必需吗？ | ❌ **净负**（是冗余，非有害） | 实测（B1b vs B2 只差一个开关，四项全胜） |
| 通道屏蔽 c 有效吗？ | ❌ 失败（压平陷阱，保留率 76.6%） | 实测 |
| 扩散比回归好吗？ | ❌ 净负 | 实测 |
| 模型太小吗？ | ❌ **不是**（头 0.008% 参数拿 SOTA；dense 天花板 1.0 只做到 0.58） | 解析可算 |
| 条件信息不足吗？ | ❌ **不是**（见 7.2） | 实测（§15.14） |
| 数据量是杠杆吗？ | ✅ **是，且是历史上最大的**（V9 扩数据 −27%） | 实测 |

### 7.2 ⭐ 容量 vs 结构：瓶颈在哪

**structured 头的表示天花板（解析可算，`diag_capacity_vs_structure.py`）**

| r | shape corr 天花板 | 含义 |
|---|---|---|
| 0（纯乘性增益） | 0.4818 | |
| **2（= B1a）** | 0.6539 | |
| **8（= B1b，当前 SOTA）** | **0.8556** | ← 实测只拿到 **0.7124**，兑现 **83.3%** |
| 16（= B1c） | 0.9431 | |
| 48（无带宽限制） | 1.0000 | dense 头的天花板 |

**缺口分解**：

| 缺口 | 大小 | 含义 |
|---|---|---|
| 表示缺口 | 1.0000 − 0.8556 = **0.144** | 低通基表达不了的部分 |
| 实现缺口 | 0.8556 − 0.7124 = **0.143** | 有条件但没选对系数 |
| （对照）dense 头总缺口 | 1.0 − 0.5797 = **0.42** | 三倍于前两者 ⇒ **归纳偏置是主因** |

**残差内在秩**（SVD of `target − exem`，动通道）：80%/90%/95%/99% 需要 **3/5/8/18** 个模态。
r=8 的 DCT 已捕获残差能量 **93.8%**，剩 **6.2% 高频尾巴** —— 但 shape corr 定义在**一阶差分 Δ** 上，
**对高频极敏感**，这 6.2% 就值 0.144 的 corr 差距。

### 7.3 ⭐ 「条件信息不足」已被实测否证（`diag_bank_coverage.py`）

| 检验 | 实测 | 含义 |
|---|---|---|
| `action_shared`（动作被多少角色共有） | **min = 5** | 验证集**没有长尾**（被 `≥5` 过滤掉） |
| `bank_size`（该角色其它动作数） | 中位 **45**，**601/614 已饱和** | bank **从未被饿着** |
| R 臂（**不用 bank**）在同一协变量上 | 强梯度 0.086 → 0.284 → **0.592** | `bank_size` 实为「角色规整度」代理 |
| **B1b** 在同一协变量上 | **平坦** 0.703 → 0.714 | **bank 已把这个混杂消化掉** ⇒ bank 有效的正面证据 |
| 按先验误差四分 | **Q1（先验最好）相对增益 −1.6%**；Q4（最差）+53.1% | 模型在先验已好的 1/4 实例上**完全不改进** |
| 最差实例集中度 | `l2d12.ugirl09`×4 / `l2d07.ugirl06`×2 / `l2d01.ugirl201·204`×3 | 失败集中在少数**离群角色**，**其 bank 均丰（16–65）** |

⇒ **真正的失败模式 = 拟合离群角色（信息利用问题），不是欠覆盖（信息可得性问题）。**

### 7.4 当前最大的问题（按证据强度）

1. ⭐⭐ **拟合「离群角色」的能力**（**实测**）：先验误差跨 **130 倍**（0.000 → 29.45），
   而误差几乎全部来自先验最差的那 1/4；模型的修正能力在那里最弱而参考库最丰。
2. ⭐ **形状头的读出是「时间盲」的**（**【推断】，读代码得出，尚未实测**）：
   `model.py:393` 的 `h_pool = h.mean(dim=2)` 把整条 T 轴压成一个向量**之后**才算 α/coef。
   形态上直接对应 0.143 的实现缺口。头部只有 3465 参数 ⇒ 修它的增量成本可忽略。
3. **长尾完全未测量**：**16.1% 的训练样本从不被评估**。
4. **口径双峰**：0.7124 掩盖了 26% >0.9 与 7.1% <0.25 的两极。

### 7.5 建议的下一步（按性价比）

| # | 动作 | 成本 | 针对 |
|---|---|---|---|
| 1 | **给形状头加时间感知读出**（`mean(dim=2)` → attention pooling over T） | 极低（头 0.008% 参数） | 7.4(2) |
| 2 | **按实例难度重加权损失**（先验越差权重越高） | 低 | 7.4(1)；先例：量程修复 / `span_w=1` 都是重加权 |
| 3 | **补长尾 val 切片**（角色专属动作） | 低 | 7.4(3) —— 目前**零数据** |
| 4 | **rank 扫描**（r ∈ {2, 8, 16}）分离表示/实现缺口 | 中（每臂 ~8h，4 卡） | §7.2 |

**建议放弃**：单纯放大 `d` / 加深 `temporal`（§7.2 已否证）。

## 9. 关键术语表

| 术语 | 含义 |
|---|---|
| **`exem`** | 跨所有角色的同（动作，参数）均值曲线。**核心先验 / 基线** |
| **`rig`** | 96d 静态角色签名（方差最大的 48 个参数的 z-score 量程与均值） |
| **`rig_loo`** | 构造 rig 时排除目标动作，避免泄漏目标幅度（**必须开**） |
| **`bank`** | 该角色**其它动作**的曲线库，K=8 条逐参数交叉注意力 |
| **`cstats`** | 5d 逐参数角色统计（rest/幅度/lo/hi/支持数）—— **实测是死的** |
| **`dense` / `structured` 头** | 输出头的两种形态（见 §3.4） |
| **`shape corr`** | 一阶差分 Δ 上的相关系数，**逐实例算再取均值**（口径见 §6.2 #4） |
| **保留率** | `mean|Δpred| / mean|Δtgt|`，判断 dMAE 优劣是否来自压平 |
| **常数通道** | 目标在时间上恒定（ptp<1e-6）的通道，占 **43.2%**，纯幅度无形状 |
| **动通道** | 非常数通道，占 **56.8%**，形状判据只看它 |
| **表示缺口 / 实现缺口** | 见 §7.2 |
| **压平陷阱** | dMAE 低但只是曲线更平（保留率远低）—— 必须用 `diag_shape_floor` 否证 |

## 10. 重新评估时的建议清单

把这几个问题先定下来，后面的方向会清楚很多：

1. **要不要把长尾纳入评估？** 现在 16.1% 的训练样本从不被评分。
   如果不纳入，投在长尾上的精力**永远无法被验证**。
2. **主判据到底用 `shape corr` 均值，还是「双峰 / 尾部比例」？**
   均值 0.7124 掩盖了 26% 近乎完美 + 7% 完全失败。
3. **「已知动作、新角色」是不是真实部署场景？**
   如果不是（例如也可能遇到**角色专属动作**），那当前 26.5% 的动作覆盖率就是硬约束。
4. **接受「扩散净负」这个结论吗？** 它意味着这条路线上不再投扩散。
5. **rank 扫描（表示缺口）与新读出（实现缺口）先做哪个？**
   两者各占 0.14，但成本差 100 倍。
