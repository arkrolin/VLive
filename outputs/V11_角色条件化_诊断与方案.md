# V11：角色条件化（诊断 + 方案）

> 起因：R 臂（当前最佳，全量 614 / exem 先验 1.5196）abs_mae 0.9202，数字好看，但渲染出来的曲线肉眼就是不对。
> 本文记录「为什么数字好看但视觉差」的根因定位，以及由此确定的 V11 设计。
> 所有数字来自 `outputs/diag_ref_prior*.py`，口径为 **未加权原始单位 abs_mae**（与官方 span 加权的 0.9202 不同尺度，只做内部相对比较）。

---

## 1. 根因：模型只学到了幅度，没学到形状

| 口径 | exem 先验 | R 模型 | 改进 |
|---|---|---|---|
| 逐点 MAE | 1.6242 | 0.9778 | **+39.8%** |
| 一阶差分 MAE（形状） | 0.1548 | 0.1515 | **+2.1%** |

这一条解释了此前所有的困惑：

- 为什么 MAE 好看但视觉差 → MAE 由幅度主导，形状几乎没学
- 为什么预测的形状相关性（0.654）比先验（0.662）还差
- 为什么结构化低秩头（S 臂，约束形状）无效
- 为什么后处理平滑无效

**为什么学不到形状？** 因为幅度是从 rig 特征泄露进来的（见 §3），而形状需要对角色成立体化理解，held-out 角色只有 1 条 (角色, 动作) 观测，不可学。

### 2.1 关键结论

1. **角色自身动作库是真信号，不是统计偏差。** 同池大小（~22 条）换成别的角色，误差 0.5031 vs 3.3719（6.7×）；换成更大的跨角色池（90 角色）也只有 1.7673（3.5×）。

2. ⭐ **聚合方式在跨角色 / 角色内完全相反** —— 这是架构设计的决定性依据：

   | | 平均 | 选择（oracle） | 结论 |
   |---|---|---|---|
   | 跨角色 | **1.6242** | 1.9554 | 候选之间是噪声关系，平均能抵消 |
   | 角色内 | 1.8510 | **0.5031** | 候选是语义不同的动作，选择好 3.7× |

   → **必须逐参数交叉注意力 / 软检索，任何池化、平均、单锚点都会毁掉信号。**

3. **「用角色共有的 stand 动作当锚点」被证伪。** IDLE 覆盖率 94.5%（580/614），但直接当先验 2.2758、delta 2.2722，都远差于 exem。推广版（整个库 + 选择）才成立。

4. **naive 可部署检索失败**（1.3938 vs 模型 0.9778）→ 选择函数必须是学出来的，不能用 exem 相似度硬检索。

## 3. rig 96d 泄露了目标幅度

`build_model_identity` 用角色**全部动作（含目标动作）**聚合 per-param (min, max, mean)：

- 目标 range / 角色全局 range：中位 0.128、均值 0.309
- **29.2% 通道目标贡献 ≥50% 全局 range，5.2% 完全独占**

**零成本量化**（只改评估时喂给模型的 rig，权重不动）：

| 口径 | abs_mae | vs exem |
|---|---|---|
| R best + leaky rig（原报告） | 0.9202 | +39.4% |
| R best + **LOO** rig（诚实值） | **0.9481** | +37.6% |

→ 泄露值 **0.0279 = 3.0%**。真实存在但不主导。
⚠️ **R 的公平基线是 0.9481，不是 0.9202。**

## 4. 具身智能调研的对应

- 「exem 跨角色平均」= 具身智能的 **conservative averaging**（OmniXtreme 明确点名：动作库变大后策略趋向保守平均）。业内解法是 flow-matching 预训练 + **残差 RL 后训练**，不是改先验。
- **解耦范式**（OmniHumanoid 分支隔离注意力 / MotionCrafter 时空双分支 / Customize-A-Video 的 Appearance Absorber）→ 对应我们：**身份流（角色自身动作库编码）与动作语义流（标签 + 跨角色先验）显式分离**。
- MOTIF 的领域对抗（抹掉本体身份）**不适用**（我们无多本体问题）。
- VQ / 离散 token **不要抄**（MAE 下量化就是误差地板）。
- 形状口径：角色库单动作 oracle 0.2233 **差于** exem 0.1548 → **角色库单独用不给形状，必须与现有模型融合，不能替换。**

## 5. V11 设计

### V11a：角色统计特征（数据侧修复，不动架构）

1. **rig leave-one-out**：剔除目标动作对 (min, max, mean) 的贡献。新缓存存 per-param 的 `(min1, min2, max1, max2, sum, cnt)`，次小/次大值保证 LOO 极值精确；无支撑的通道置 0（未知）而非回退到泄露值。
2. **per-token 角色统计特征**（5 维，LOO 预计算）：静息值 / 典型幅度 / 下界 / 上界 / 支撑数。经**零初始化**的 `Linear(5, d)` 加进 token 嵌入 → 起步与基线逐位相同。

归一化：`rest/lo/hi` 按 `(v − lo)/span`，`amp` 按 `/span`，`log1p_cnt` 不动（clamp ±6）。

### V11b：角色动作库逐参数交叉注意力

- 每个样本携带该角色 **K=8** 条其它动作曲线（目标动作严格排除，crc32 播种保证各 DDP rank 一致）
- 参数 token 做 query，K 条参考曲线做 kv，`scores[b,p,k] = ⟨q[b,p], kv[b,k,p]⟩`
- 检索出的曲线作为**第 3 个输入通道**喂给 `in_proj`，该通道权重零初始化；`bank_gate` 零初始化标量
- 上界：逐参数 oracle 0.5031

### 验证

- `_bank_refs` 采样 K 均值 7.3 / 上限 8，**目标动作泄露 0 次**
- **no-op 逐位验证：`max|attn − base| = 0.000e+00`**
- 注意力熵 0.467（均匀应为 2.079）→ 起步即明显集中
- 梯度打开验证：head 第 1 步、`bank_gate` 与 `char_stats_enc` 第 2 步、in_proj 第 3 通道第 6 步已增长 → 分支不会训死
- ⚠️ init 时 bank 分支梯度全为 0 是**预期的**（head 也是零初始化 → out == exem → 上游无梯度）

## 6. ⭐ V11a 结果：新最佳（全量 614，2026-09-11）

| 臂 | 配置 | abs_mae | vs exem(1.5196) | vs R 公平基线 |
|---|---|---|---|---|
| **V11a** | R + rig LOO + per-token 角色统计 | **0.8720** | **+42.6%** | **+8.0%** |
| V11a latest (ep70) | 同上 | 0.8764 | +42.3% | +7.6% |
| R+rigloo（公平基线） | R best，评估时喂 LOO rig | 0.9481 | +37.6% | — |
| R（原报告，leaky rig） | R best | 0.9202 | +39.4% | — |

- **best(ep69) 0.8720 / latest(ep70) 0.8764，两者差 0.5%（噪声内）→ 已收敛，不是过拟合。**
- 训练内 117 子集：V11a 1.3667 vs R 1.4940（好 8.5%），与全量口径一致。
- **配对检验（`compare_dumps.py`，逐参数实例对齐 n=37546）**：diff = +0.0761（R 更差），**t = 2.64 → p < 0.05，显著。**
- GATE: PASS。`rel_f` 0.0106（exem 0.0143）。

### 6.1 解读

1. **V11a 是纯数据侧修复**（rig 去重 + 把角色统计显式喂给 token），**没有动架构**，却拿到了 8% 提升 —— 再次验证 §6 的判断：本项目的杠杆在数据/统计侧，不在架构侧。
2. 但提升幅度（8%）**小于** §2 里角色库 oracle 的上界（0.5031 vs 0.9778，+48.6%）——说明 per-token 5 维统计只吃掉了「静息值/幅度」这一层，**没有吃到「形状选择」那层**（§2.1 结论 2：角色内必须*选择*，不能平均/池化）。这正是 V11b 要解决的。
3. ⚠️ **此后所有比较的公平基线改为 0.9481（R+rigloo）**，0.9202 含 3.0% rig 泄露，不可用作对照。

### 7.2 幅度 vs 形状（614 样本，修复后同脚本同版本）

| 指标 | V11a | R | 变化 |
|---|---|---|---|
| point MAE（幅度主导） | **0.9230** | 0.9785 | **+5.7%** |
| delta MAE（纯形状） | 0.1531 | **0.1513** | −1.2%（噪声内） |
| shape corr | **0.5960** | 0.5835 | +1.2% |
| 　point MAE｜常数通道 | **0.6951** | 0.7993 | **+13.0%** |
| 　point MAE｜动通道 | **1.0233** | 1.0592 | +3.4% |
| 　delta MAE｜动通道 | 0.2189 | **0.2184** | 持平 |

### 7.3 解读

1. **因果链闭合**：5.7% 的整体提升**绝大部分来自常数通道 +13.0%**（静息值预测），
   这正是 per-token 角色统计里 `rest` 那一维的设计目标 —— 改动生效在它该生效的地方。
2. ⚠️ **形状依然没有改善**：delta MAE −1.2%（噪声内）、动通道 delta 完全持平。
   **V11a 本质上仍是「只改幅度不改形状」的补丁**，与 §1 诊断的 R 的问题同类。
3. → 要靠数据赢形状，只能靠「**从角色动作库里选择**」（§2.1 结论 2：角色内选择 0.5031 vs 平均 1.8510，3.7×），
   而不是「给模型更多统计量」。**V11b（逐参数交叉注意力）的必要性由此被直接验证。**
4. 常数通道占 43.0%，且目前误差 0.6951 —— 相比角色库 oracle 的 0.0298（§2.2），**常数通道仍有巨大空间**。

### 8.1 ⭐ 分支消融（ep16 ckpt，全量 614）——决定性的机制证据

工具：`outputs/diag_bank_ablation.py`。同一 ckpt 跑三遍，把某个分支的输入**置零**
（两个分支都是零初始化，置零 = 回到该分支自己的起点，是最诚实的消融）：

| 配置 | abs_mae | vs exem(1.5196) | rel_f |
|---|---|---|---|
| **full**（cstats + bank） | **1.1665** | **+23.2%** | 0.01513 |
| **no-bank**（只留 cstats） | **2.1129** | **−39.0%** ❌ | 0.02345 |
| **no-cstats**（只留 bank） | 1.1737 | +22.8% | 0.01512 |

**结论（强）**：

1. **增益 100% 来自 bank**。关掉 bank 后模型**比 exem 先验还差 39%** —— 说明 cstats 单独根本撑不住，
   而 bank 是唯一的实际信息源。
2. **cstats 分支基本是死的**：关掉只退化 0.6%（噪声内）。⚠️ 这与 V11a 的结论**不矛盾但口吻要修正**：
   V11a 里 cstats 有效（+5.7%，全在常数通道）；**V11b 里 bank 更强，cstats 被完全替代**
   —— bank 里已经含了角色统计的全部信息（参考曲线本身就编码了静息值和量程）。
3. 直接印证 §2.1 结论 2 与 §7.3：**精度要靠「角色内*选择*」，不是靠统计量。**
4. 工程推论：**V11b 的架构可以砍掉 cstats 分支**（省显存/参数），或保留但不必再投入。
   下一轮该做的是 **bank 侧的深化**（更大 K、更好的选择函数），不是加统计特征。

#### 为什么？损失函数里根本没有形状项

`train.py` 的训练损失是：

```python
se = (x0_hat - x0) ** 2                      # 逐帧逐点 MSE，只有「电平」
loss = (se * valid).sum() / valid.sum()      # valid = token_mask × 幅度权重 × span^span_w
```

- **没有一阶差分 / 导数 / DCT 形状项**（`grep diff\|delta\|deriv` 在损失路径上无命中）。
- `span_w>0` 时注释写得很明白：「span_w=2 makes this raw-unit MSE, i.e. **the loss then optimises abs_mae**」。
- 也就是说：**目标函数优化的就是验收用的那个指标（abs_mae）**，而 abs_mae 被 43% 的常数通道主导。
  形状不是被"学不会"，而是**从来没被要求学**。这解释了 R / V11a / V11b 三臂形状指标都趴在 exem 水平线上。

### 15.1 现架构的结构性缺陷（代码审计）

审计对象：`src/live2d_vla/model.py`（`Live2DModel.forward`）、`train.py::noise_loss`、`config.py`。

**当前（V11b）数据流**：

```
chan = [x_t, exem, (bank_att)]              # 三路直接在「值域」上拼接
h    = in_proj(cat(chan,-1))                # (B,n,T,d)
h    = temporal_blocks(h) ⊕ token_mixer(h)  # over T / over P
out  = head(h)                              # nn.Linear(d,1) → (B,n,T)
x0_hat = exem + g * out                     # g = residual gate (name)
```

**缺陷 1 —— 幅度与形状共用一个 head、一个损失，无结构分工。**
`head` 是单个 `Linear(d,1)`，输出整张 P×T 残差矩阵。**幅度**（曲线的电平/尺度）与**形状**（曲线的时间走势）被编码在同一组输出里，也由同一个 loss 同时打分。优化器没有任何机制促使二者分工 —— 谁容易降 loss 就先降谁，实测结果是**幅度吃掉了全部收益**（§1、§12.4 的因果链：R→V11b 的 +10.2% point 增益全部来自幅度，delta 反而 +4.9% 变差）。

**缺陷 2 —— `in_proj` 把三路条件在值域上拼接，幅度信息与形状信息未分层。**
`x_t / exem / bank_curve` 都是「形状 + 幅度混在一起」的曲线张量。把它们 concat 后交给同一组卷积，模型没有显式通路去区分「这条曲线整体该多高」与「这条曲线该怎么走」。

**缺陷 3 —— 形状项与电平项共用同一个 `valid` 权重与同一个分母。**
`train.py:373` 的 shape 项复用 `valid`（= `token_mask * arm_w * span_w 加权`）和 `valid.sum()`。这意味着**形状项的加权口径被电平项绑架**：常数通道（43.2%）在电平项里权重很大（它们吃掉了相当一部分 point 误差），在形状项里却是恒等于 0 的无效监督（目标 Δ≡0），却被算进分母、稀释了能动通道的形状信号。

**缺陷 4 —— 已实现但从未启用的 `head_mode="structured"`。**
`model.py:206-224, 378-384` 已有一段**结构化头**分支（`gain_head: Linear(d,1)` per-param 幅度增益 α∈R^P ＋ `coef_head: Linear(d,r)` × DCT-II 低频基），合成式 `out = exem*(1+α) + coef@basis`。**这正是本轮 b 方向想要的「幅度-形状解耦」原型，代码是现成的，只是没跑过**。`residual_gate="name"` 亦已实现（按参数名学「何时不该用残差」）。

**缺陷 5 —— 验收闸只看电平口径。**
现闸门（`abs_mae / val_rel_mae_f / train_loss`）**全部是电平口径**，对形状完全不敏感 → §14 已证会把「形状首次翻正」的 V11c 判成负收益（abs_mae +11.5% 差 / delta −10.0% 好）。**闸门必须先修，否则下一轮的 b/c 一定被误判。**

### 15.2 零样本生成文献：可迁移的架构范式

调研了零样本 TTS（AuK / VoxCPM / WhisperVC / NaturalSpeech 2 / CosyVoice 2）与具身智能（Libra-VLA / HiPolicy / Discrete-Diffusion-VLA）。**结论高度一致：领域内已形成共识 —— 「规划」与「渲染」必须在架构上分工，靠单个 head + 单个 loss 学不出来。**

#### (a) VoxCPM（ICLR 2026，清华 + 面壁）—— 与本项目问题陈述**几乎逐字对应**

> 连续表示路线……**语义-韵律规划与声学渲染被强行塞进同一个学习目标**，模型既当全局规划师又当局部渲染师，缺乏天然的架构分工，注意力被低层声学纹理拽走，长序列上误差累积。

**解法**：可微 **FSQ 半离散瓶颈作「正则化」而非「预测目标」**。`h_TSLM`（稳定语义骨架）过 FSQ → `h_FSQ`；`RALM` 专门拟合**被量化丢掉的那部分残差** `h_residual`；两者**相加** `h_final = h_FSQ + h_residual` 驱动局部扩散解码器（LocDiT）。
**关键消融（硬数字）**：去掉 FSQ → 困难集中文 **CER 18.19% → 24.92%（+6.7 点）**；FSQ 维度过小（d=4）过度约束韵律、过大（d=1024）离散化不足，**最优在 d=128/256**（倒 U 型）；去掉残差声学分支（RALM）或预训练 LM 初始化均显著掉点（WER 2.98 → 5.24）。
**T-SNE 证据**：TSLM-FSQ 按**文本内容**聚类，RALM 残差按**说话人身份**聚类 —— **无需显式监督即自然分工**。

> **→ 对应我们**：FSQ 瓶颈的等价物是 **per-param 幅度标量瓶颈 α∈R^P（低维、强制过滤掉细粒度信息）**；`h_FSQ + h_residual` 的等价物是 **`exem*(1+α) + shape`**。「瓶颈维度有倒 U 型最优」直接支持对 α 的**表示形式**做扫描（标量 / 低秩 / 有界分箱）。

#### (b) AuK（腾讯混元语音）—— **双流 + 独立残差通路**

① **双流 MMDiT（前 10 层）+ 单流 DiT（后 20 层）**：语义流与声学流**各自保留独立残差通路**，仅在联合注意力中交换信息（FLUX 风格），**不做早期拼接**（对照我们的缺陷 2：`in_proj` 正是「早期在值域上拼接」）。
② 语义条件取 LLM **逐层隐状态可学习加权和**（32 层全保留，不固定取最后一层）。
③ 零样本数据构造改为**跨句配对**（同说话人 n 条录音两两配对 → n×(n−1) 双向样本，**迫使模型分离「说话人是谁」与「说了什么」**）。
④ rectified flow + 蒸馏（一致性初始化 + 解耦 DMD）。

> **→ 对应我们**：③ 与我们的 **V11b bank attention 是同一思路**（用「该角色其它动作」当 in-context 参考，逼迫分离「角色风格」与「这个动作是什么」）—— 这条我们已走通，无需再抄。① 才是新的：**幅度流与形状流先各自编码、后期才交互**，而不是先 concat。

#### (c) WhisperVC / FELLE-CoD —— coarse-to-fine 残差分解

`mel = M_c（coarse 全局结构，L1 确定性）+ R（残差细粒度细节，OT-CFM）`，明确表述为 **"coarse-to-fine formulation separates global structure modeling from stochastic detail refinement"**。CoD 逐级 `x = Downsample(x_c) + Upsample(x_c 的残差)`。

> **→ 对应我们**：`x̂ = 低频骨架 + 高频残差`。可直接用 **DCT 低频（即现有 `basis`）当骨架、密集头补残差**，两级各用各的 loss。

#### (d) CosyVoice 2 —— 明确**抛弃 speaker embedding**，理由：它**泄漏了音频的韵律信息**

> **→ 对应我们**：与我们「`rig` 96d 泄漏目标幅度」的问题**同构**，且我们已用 `rig_loo` 处理（§3）。这条**再次验证** LOO 的必要性，同时提示：**任何「角色静态签名」都很容易连带泄漏幅度**，b 方向里若给幅度头注入 rig，必须继续 LOO。

#### (e) 具身智能侧

- **Libra-VLA（ACL 2026）**：诊断与 VoxCPM 同构 —— 现有 VLA「**monolithic generation paradigm**，直接把视觉-语言特征映射到高频 motor commands，**忽视 manipulation 的内在层次结构 → semantic-actuation gap 过大、representational burden 过重**」。解法：把 action 分解为**离散 coarse intent（Semantic Planner）+ 连续 fine alignment（Action Refiner）**，异步执行。
  ⭐ **关键可迁移结论**：**性能随 coarse bin 数量呈倒 U 型曲线**，在 N=10 达到平衡点（"Libra point"）→ **离散/有界瓶颈的容量必须扫**，不能想当然取大或取小（与 VoxCPM 的 d 扫描一致）。
- **HiPolicy（arXiv:2604.06067）**：**多频分层双分支** —— LF 分支抓 long-horizon 意图、HF 分支抓精细调整，联合训练。
  ⭐ **消融**：`w/o hierarchical freq. structure: 60 → 37`（−38%），**比 feature fusion 的贡献（60→54）大得多** → **「分层拆分本身」才是主增益**，融合方式只是次要。
  另：`低熵→执行高频块 / 高熵→执行低频块` 的 entropy-gated execution，可作为我们**不确定性驱动的通道级调度**的类比。
- **Discrete-Diffusion-VLA**：把 action 离散化后用 **masked-token 恢复**建模，实现**自适应解码顺序**（先定高置信元素，再回头修不确定项）+ 二次 re-masking 纠错。对照我们的 P×T 输出：**不需要所有 (参数,帧) 同时确定**。
- **π0（Physical Intelligence）**：VLM 主干 + **独立权重的 action expert**（流匹配），动作 token 用**另一套权重**而非共享。→ 支持「**专用头 / 专用权重**」而非单一 head。

#### (f) 反例警示（本院 §4 已确立，继续有效）

- ⛔ **VQ / 离散 token 不可抄**（MAE 下量化 = 误差地板）。但 ⚠️ 注意区分：VoxCPM 的 FSQ 是**作正则化的瓶颈**（内部、可微、非预测目标），不是「把输出量化成 token」。**我们抄的是前者**（连续瓶颈 + 残差），不是后者。
- ⛔ 领域对抗（MOTIF 式抹身份）不适用。

### 15.3 ⭐ c 方向的前置修正：原命题的前提有误（**实测推翻，先改再跑**）

§14.6(c) 的原表述是：

> 「常数通道（43%）几乎纯幅度，动通道（57%）才是形状 → 形状项**只作用在动通道**可避免 λ 在常数通道上白耗幅度」

这是**想当然**。我用 `outputs/render_data/abl_R_all_v9_best.pkl`（614 样本，37546 个 (实例,参数) 槽位）**直接量化**了这个命题，结论是**原前提不成立**：

| 检查项 | 实测值 | 含义 |
|---|---|---|
| `const_frac`（ptp<1e-6） | **0.4316** | ✅ 与报告 43.2% 一致，口径无误 |
| ptp 分布 | p10=0, p25=0, **p50=0.20**, p75=1.00, p90=3.55, p99=44.3 | **强双峰**：要么恒等于 0，要么有意义运动，中间几乎没有 |
| 阈值敏感性 | `ptp>1e-6 / 1e-4 / 1e-3 / 1e-2` → keep 均为 **56.8%** | 门控**极稳健**，不挑阈值 |
| **低动通道占形状损失质量** | **0.0%** | 常数通道 Δ≡0 → **形状项对它们的“目标”贡献本就为 0** |
| 屏蔽前后形状损失 | 未屏蔽 6.6538 → 屏蔽 9.8489（**×1.480**） | ⚠️ 屏蔽让损失**变大**，不是变小 |
| 分母变化 | 1764662 → 1002839（**×0.5683**） | 等效把 λ 放大约 **×1.76** |
| 低动通道的 `mean\|Δpred\|` | **0.0293**（全通道 0.1837） | 常数通道上模型**仍有抖动**，这部分被计入损失 |
| 移动通道占 **point 误差** | **74.4%**（而只占 57.0% 槽位） | ⚠️ 幅度误差也主要在动通道，不在常数通道 |

**推论（三条，全部改变方案）**：

1. ⛔ **「常数通道白耗 λ」的说法是错的 —— 但要分清哪一侧为 0**。常数通道的**目标侧**形状项恒为 0（Δ_target ≡ 0），所以屏蔽它们**不会省下任何「目标拟合」的 λ**。真正被去掉的是**预测侧的抖动惩罚**（`(Δ_pred − 0)²`，实测低动通道 `mean|Δpred| = 0.0293`）—— 那是**「不许乱抖」的正则**，不是白耗。
2. ⭐ **屏蔽的真实作用 = 「把形状梯度全部集中到能动通道」**，代价是损失尺度 ×1.48 —— 这是一个**重新加权**，不是节省。屏蔽后模型不再被要求在「目标恒定」的地方强行不抖，而是把全部容量用于拟合真实运动。**方向仍是对的**（把容量给真形状），但**机理与原表述完全不同**：不是省钱，是改预算分配。
3. ⚠️ **λ 必须随屏蔽重标定**：分母从 1764662 → 1002839（**×0.5683**），即形状项被等效**放大约 ×1.76**。**直接沿用 λ=20 会变成 ≈λ=35 的有效强度** —— 而 §14.5 已证 20 已饱和、50 是纯浪费。**所以 c 臂必须重扫 λ，不能只改 mask。** 若要「保持与原 λ=20 相同的有效强度」，应取 **λ ≈ 20 × 0.5683 ≈ 11**；文档 §15.5 取 **10** 作为该工作点（略保守，因为屏蔽本身还去掉了一个有益的正则项）。

> **诚实记录**：这是一次**基于实测推翻自己上一轮方案前提**的过程。原方案若照跑，会得到「屏蔽通道 = 无变化或轻微变差」的结果，并被误读为「按通道加权无效」；真相是**有效 λ 被同时放大了 ×1.76（分母效应）**，两个效应混在一起，无法归因。

### 15.4 下一轮方案（b / c）

#### b. 幅度-形状解耦

**b1 — 启用现成的 `head_mode="structured"`（零新代码）**
`head_mode="structured"`, `residual_rank=r`。结构：`out = exem*(1+α) + coef@DCT_basis(r)`，α 与 coef 均由 `h_pool = h.mean(dim=2)`（**pool over T**）出。全零初始化 → 起步与基线逐位一致。
- **已实现的偏置**：α 只做到**乘性增益**（`exem*(1+α)`），不能表达「目标与先验不同号」的幅度修正。可在 b2 里补加性项。
- **(r 扫描)**：`r ∈ {2, 4, 8, 16}`。依据：VoxCPM 的 FSQ 维度倒 U 型 + Libra-VLA 的 bin 倒 U 型 → **低秩容量必须扫**。⚠️ 历史教训：`rank=2` 的 S 臂全量 0.9779 反差于 R dense 0.9202（−6.3%），memory 明确「rank 太低、约束过紧」→ **b1 的扫描重点在 r≥4**。

**b2 — 加性幅度 + 形状（补 b1 的表达缺口）**
`out = exem*(1+α) + d_amp + coef@basis`，其中 `d_amp = amp_head(h_pool)`（per-param 标量），实现「先验整体抬高/压低」的加性修正。b1 与 b2 可作一组对照，隔离「乘性 vs 加性幅度」。

**b3 — 双流（借鉴 AuK 缺陷 2 的修法）**
不动 `in_proj` 的三路拼接，而是在**输出端**分两条路：`amp_head`（pool over T，出 α∈R^P）与 `shape_head`（保留 T 维，出 (B,n,T) 形状残差），合成 `x̂ = exem*(1+α) + shape`。
- 与 b1/b2 的区别：b1/b2 的 shape 被**限制在 r 个低频基**上；b3 的 shape 是全维 dense，但**幅度被强行抽走**（pool over T 后再广播）。
- 这是「**两个专用头 + 专用权重**」（π0 的 action expert 思路），也是「独立残差通路」（AuK）在输出层的实现。

**b4 — 形状头只用 DCT 低频、密集头补高频（CoD 式分级）**（备选，优先级最低）

#### c. 按通道加权（先修前提，再跑）

**c1 — 形状项独立 motion mask**
在 `noise_loss` 里为 shape 项**单独**构造 `m_mov = (ptp_target > ε)`（`ptp` 在**原始单位**上、按样本逐通道算），用它替换 shape 项的 `valid`，并使用**自己的分母** `m_mov.sum()`：

```python
if shape_w > 0:
    d_hat = x0_hat[..., 1:] - x0_hat[..., :-1]
    d_tgt = x0[..., 1:] - x0[..., :-1]
    sd = (d_hat - d_tgt) ** 2
    if shape_motion_mask > 0:            # NEW
        ptp = (target.amax(-1) - target.amin(-1))        # 原始单位 (B,n)
        m_mov = (ptp > shape_motion_mask).unsqueeze(-1).float()   # (B,n,1)
        sw = valid * m_mov                # shape 专用权重
    else:
        sw = valid
    loss = loss + shape_w * (sd * sw).sum() / sw.sum().clamp(min=1.0)
```
- `ε` 取 `1e-3`（实测 1e-6~1e-2 等价，取中值稳妥）；**默认 0 = 保持旧的逐位行为**。
- ⚠️ **必须同时重扫 λ**（见 15.3 推论 3）。

**c2 — 反向加权（可作对照臂）**
既然结论是「动通道承担 74.4% point 误差 + 全部形状误差」，另一条路是**给电平项也按 ptp 加权**（让动通道的电平误差被重视）而**不是**屏蔽常数通道。这与 c1 是**互补**假设，值得并列测。

### 15.12.4 裁决

| 问题 | 证据 | 结论 |
|---|---|---|
| structured 头（幅度-形状解耦）本身有用吗？ | B1b vs V11b：abs_mae −6.2%、corr +22.9%、point MAE −6.9% | **✅ 有用，且是本轮唯一真正的收益来源** |
| 加性幅度项（b2）必需吗？ | **B1b vs B2 单变量**：abs_mae 0.7871 vs 0.8139、corr 0.7124 vs 0.6982、pt｜常数 0.5738 vs 0.5764、保留率 91.8% vs 90.6% | **❌ 净负。四指标一致否证 ⇒ `head_additive_amp` 应默认关闭** |
| c 方向（动通道重加权）有效吗？ | C1a：abs_mae 0.9229、corr 0.5897、保留率 76.6% | **❌ 失败。屏蔽梯度没能提升动通道形状，反而整体压低幅度** |
| D1（b2 + c1 组合）翻盘了吗？ | D1 abs_mae 0.8037 vs B1b 0.7871；corr 0.7026 vs 0.7124 | **❌ 不优于 B1b** |

⭐ **一句话**：本轮唯一真正有效的架构改动，是 **structured 头本身**（乘性 `gain_head` α + DCT 低秩
`coef_head`），其单臂 **B1b 即新 SOTA**；**加性幅度项**与**动通道屏蔽**两项增补**均为负贡献，应移出主线**。
