# Live2D 方案 V7 — 生成模型架构与训练设计

> 承接 V4（跨角色可迁移性 / 手势语素）、V5（数据缩放律 / FOCUS 清单）、V6（来源多样性 / 静态 rig 恢复）、V6.1（B1 实证）、V6.2（来源自动匹配 / 扫掠探针增益）、V6.4（同来源自动检索产品化）。
> 本文把上述**实证结论逐一翻译成架构约束与训练协议**，给出可直接落地的生成模型设计。

---

## 0. 问题定义回顾

- **任务**：输入 = 自然语言动作描述 + （可选）参考视频（同角色已有 Live2D 动画）+ few-shot 配置；输出 = 目标角色 `.motion3.json`（20 通道 CANON 曲线 + 常量通道作者注入 + M3 数字部件补充）。
- **硬约束（V3 用户决策）**：① 常量通道注入作者实际值；② 播放器跑物理演算，模型不生成物理；③ 数字-only 部件 M1/M2 排除、M3 补充。
- **核心需求（用户澄清）**：生成模型必须解决"**语料里没有可检索旧版本**"的情形（即零素材目标角色）。一次性表演动作为首期范围；输出须覆盖身体 + 手臂；无需人工二次编辑。
- **已落地的兜底路径**：B1 = 跨角色同动作 Live2D 示例（CANON 归一化，零素材可用，已实证 + 产品化，`deploy/rig_retrieval/`）。

## 1. 设计依据：实证结论 → 架构约束

| # | 实证结论（出处） | 翻译成的架构 / 训练约束 |
|---|---|---|
| 1 | `f(char,action) ≈ μ + rig(char) + act(action)`（V4/V6 分解） | **加性分解架构**：输出 = 均值 + rig 分支 + 动作分支，三路显式相加 |
| 2 | rig 项是**角色级**；同源兄弟的 rig 贡献为负，只有目标自有片段才能给正 rig（V6 exp H） | rig 分支**只吃静态信息**（moc3 参数集 + 扫掠探针），**绝不吃目标自身运动曲线**；且在架构上把 rig 与动作解耦，防止 B1 示例冒充 rig |
| 3 | 动作先验**来源局部**（V6 exp E：同源 +9.1% vs 异源 +1.0%） | 示例条件化用 **Jaccard 加权注意力**，同源示例天然权重更高 |
| 4 | 来源局部性是**编舞风格**而非命名方言（V6 exp F：收窄共享通道只消除 26%） | 示例要喂**曲线本身**（风格），而不只是动作标签 |
| 5 | B1 成立且 K=3 足够（V6.1：action-R² +0.138，达 K=8 的 84%；同源 +0.141 > 异源 +0.090） | 示例输入 = **3 条检索到的跨角色同动作曲线**；优先同源 |
| 6 | 静态 moc3 存在性零片段恢复 **36%** rig 项；探针抬到 **53%**（V6 exp I / V6.2） | rig 编码器输入定义为「参数集存在性(20) + 探针 mobility(40)」；这是零素材下 rig 项的主要来源 |
| 7 | **24.2% 不可约画师内方差** + 20 通道 CANON 是天花板（V4/V6） | 用**扩散/流匹配**建模残差分布，而非点回归；明确不追求超越该天花板 |
| 8 | CANON = 14 脸/头/身 + 6 臂，**无下肢通道**（V4） | 输出空间 = 20 通道曲线；常量通道 passthrough；物理通道交播放器 |
| 9 | 角色数优先 → 动作先验占主导；按动作均衡才能解（V5 FOCUS 清单） | 训练数据按**动作均衡采样**；文本/手势语素作为强动作信号压制先验偏置 |
| 10 | 手势语素「手放哪」跨角色可迁移（+0.96，V4） | 文本编码器额外注入**结构化空间关系**（手相对头/躯干）作为输入 |

## 2. 总体架构（加性分解生成模型）

```
            ┌──────────────── 输入三流 ────────────────┐
            │                                          │
   文本/动作 │  目标 .moc3 参数集 │  B1 检索的 3 条         │
   +手势语素 │  (静态, 零片段)    │  同动作曲线(其他角色)   │
            ▼                    ▼                     ▼
     Text Encoder         Rig Encoder           Exemplar Encoder
     (动作语义 z_a)       (角色 rig z_r)         (动作先验 z_e, 源加权)
            │                    │                     │
            │                    │                     │
            └──────────┬─────────┴─────────┬───────────┘
                       ▼                   ▼
                  R(z_r) 基曲线        A(z_a, z_e) 调制曲线
                  μ_c + rig_c(t)       act_c(t)
                       │                   │
                       └───── 相加 ────────┘
                                ▼
                        y_c(t) = B_c(t) + Δ_c(t)
                                │
                       Diffusion Denoiser (条件: z_r,z_a,z_e)
                                ▼
                  20×T CANON 曲线 → .motion3.json
                  (常量通道 passthrough / M3 数字部件补充)
```

**为什么是加性 + 扩散**：
- 加性直接对应实证分解，让 rig 瓶颈（结论 #2）在架构上被隔离、可单独训练与评估。
- 扩散处理 24.2% 不可约方差（结论 #7）——点回归会把这些方差当噪声硬拟合，扩散建模其分布，推理时可采样多样合理结果。

## 3. 输入与编码器

### 3.1 文本 / 动作编码器（z_a）
- 输入：自然语言动作描述（"挥手打招呼，幅度大，节奏轻快"）+ **结构化手势语素**（V4 的「手相对头/躯干位置」由前端 LLM 解析为定长向量）。
- 实现：冻结的中文句向量编码器（sentence embedding）映射描述 → d_a=256；手势语素拼接。若训练期缺自由文本，先用动作标签 + LLM 合成 caption 作代理（见 §7 缺口 1）。

### 3.2 Rig 编码器（z_r，瓶颈所在）
- 输入：**目标 `.moc3` 参数集**（字符串集合）→ 二值 20 维存在性 + 参数名 token 嵌入（字符级 CNN 或查表）→ set-attention 聚合 → z_r (d_r=256)。
- 可选叠加扫掠探针 mobility（40 维，存在性 20 + 各通道幅度 std 归一化 20）→ 把 rig 恢复从 36% 抬到 53%（V6.2）。
- **关键**：训练与推理时 rig 编码器**只见过静态信息**，从不接触目标自身运动 → 与零素材部署分布一致，杜绝 rig 泄漏。

### 3.3 示例编码器（z_e，动作先验）
- 输入：B1 检索返回的 K=3 条跨角色同动作 `.motion3.json` 曲线，每条 (20×T) → 轻量时序 CNN/Transformer → 示例嵌入。
- **源亲和注意力**：用检索模块给的 Jaccard 相似度作注意力权重，同源示例天然权重更高（结论 #3/#5）。这把 V6.2 的 76% 家族命中直接内化进条件化。

## 4. 生成核心（Diffusion over 曲线空间）

- **表示**：运动 = 20 通道 × T 帧的连续曲线张量（CANON 归一化）；导出时由 CANON 解码器转回 `.motion3.json` 的 Segments（需确认/补 codec，见 §7）。
- **去噪网络**：轻量扩散 Transformer。条件注入用 cross-attention 或 adaLN 接收 (z_r, z_a, z_e)。
- **预测目标**：干净曲线 y；训练用标准 ε-预测或流匹配速度损失。
- **规模**：20×T（T≈60–120）极小，扩散推理便宜，可在单卡完成，便于快速迭代。

## 5. 训练策略

### 5.1 数据协议（防止泄漏，核心）
对每条训练样本，按**零素材设定**构造输入：
- rig 输入 = 目标静态 moc3 参数集（+探针如有），**绝不**用目标自身运动曲线。
- 示例输入 = 对该 (目标参数集, 目标动作) 跑 B1 检索（自动排除目标自身角色）→ 取 Top-3。
- 文本 = 目标动作描述/标签。
→ 训练分布 = 部署分布。若某目标确有 ≥8 自有片段（A 路径），以一定概率把自有片段作为额外示例喂入，使同一模型同时学会 A 与 B1 两种设定（A 是上界放大器）。

### 5.2 课程训练
- **Stage 0 — rig 预训练**：只训 R，从静态 moc3(+探针) 预测 (目标曲线 − 动作均值)；LOCO 评估需复现 V6 exp I（36%）/ V6.2 探针（53%）。
- **Stage 1 — 动作先验**：冻结 R，训 A（文本 + 示例）预测残差；应复现 V6.1 的 +0.138（K=3）。
- **Stage 2 — 联合扩散微调**：端到端训全模型 + 扩散目标；做组件消融。

### 5.3 损失
- 曲线重建 MSE（CANON 归一化，20 通道）。
- 时序平滑（速度/加速度正则）——Live2D 曲线天然平滑。
- **通道加权**：6 条手臂通道加权提升（用户要求身体+手臂覆盖）。
- 源亲和：示例注意力已含 Jaccard 权重；可选对比损失拉拢同动作示例。
- 扩散标准损失；**常量通道排除出损失**（passthrough 作者值）。

### 5.4 数据扩充（来自 V5/V6 教训）
- 语料是角色数优先 → 动作先验占主导。**按动作均衡采样**（FOCUS 清单法）：挑首期表演动作清单，确保每个动作 ≥8 角色（top-160 ≈ 625 资产）。
- 来源多样性仅贡献 +2.7pp 先验（V6），是次要杠杆；扩语料优先挑异源 pack 拿这点增益，但**不要指望它解 rig 瓶颈**。
- 不追求突破 CANON 天花板（20 通道 + 24.2% 不可约方差）。

## 6. 评估协议（复用 audit 工具链）

沿用 V4–V6 的 **LOCO（留一角色外）** 评测，用 `tools/audit_*` 系列作基线对照，确保模型未泄漏：

| 配置 | total-R² 目标 | 说明 |
|---|---:|---|
| none（仅静态 rig） | ~0.07 | 基线 |
| 静态 moc3 | ~0.21 | 36% rig 恢复（V6 exp I） |
| + 探针 | ~0.22 | 53% rig 恢复（V6.2） |
| + B1 示例 (K=3) | ~0.22→0.40* | 动作先验注入 |
| **A 路径（自有≥8）** | **~0.66** | 上界，唯一根本闭合缺口 |

\* 注：B1 在纯回归框架下 total-R²≈0.22（V6.2）；扩散 + 更强文本/手势语素有望抬升动作先验部分，但**到 A 的剩余 ~0.44 缺口只有 A 路径能闭合**，这是结构性结论。

**组件消融必须复现审计数字**，作为模型未作弊（未泄漏目标自身运动）的健全性检查。

---

## 7. 已知缺口与风险（诚实清单）

1. **训练 caption 缺口**：语料有动作标签（`MgirlNN_pinyin`）但缺自由文本。需 (a) 用动作标签 + 手势语素作文本代理，或 (b) LLM 批量合成 caption。这是真实数据缺口。
2. **曲线↔motion3.json 编解码器**：需确认/补全 CANON 解码器（连续曲线 → Segments），否则生成结果无法落地为可播放文件。
3. **物理交接边界**：需明确哪些参数由模型生成、哪些交播放器物理演算（常量/动态 + 物理参数拆分）。
4. **B2 仍待定**：仅当只有真人参考时启用，其前端 CANON 映射误差未实测（无视频数据）。
5. **探针增益是上限估计**：用自有片段构造 mobility，真实探针受传感噪声略低。

## 8. 实施路线（分阶段）

| 阶段 | 产出 | 退出标准 |
|---|---|---|
| P0 | 确认 CANON 编解码器 + 物理通道拆分 | 曲线可往返转 .motion3.json |
| P1 | Rig 编码器（静态 moc3 → z_r）预训练 | LOCO 复现 V6 exp I 36% / V6.2 探针 53% |
| P2 | 示例编码器 + 源亲和注意力（接 `deploy/rig_retrieval`） | 复现 V6.1 B1_k3 +0.138 |
| P3 | 扩散生成核心 + 加性组合 + 课程训练 | 组件消融复现审计数字 |
| P4 | caption 合成 / 动作均衡采样（FOCUS 清单） | B1 配置 total-R² 接近上界预期 |
| P5 | A 路径融合（自有片段作可选示例） | 自有≥8 时 total-R² → ~0.66 |

**下一步建议**（待你拍板）：先落地 P0（编解码器 + 物理拆分）与 P1（rig 编码器），因为 rig 项是零素材下的主要瓶颈且已有数据背书，风险最低、收益最确定。
