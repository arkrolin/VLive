# Live2D 方案 V7.1 — 架构修订（吸收 V1 调研报告 + V2 方案设计）

> 本文是 V7《生成模型架构与训练设计》的修订版。读 V1《VLA与具身智能扩散动作生成_深度调研报告》与 V2《Live2D动作生成_方案设计V2》后，发现 V7 的若干设定需要修正——**核心是把"固定 20 通道输出"改为"参数即 Token"，并把 rig 编码器、通道处理、数据引擎、评测空间按 V2 重写**。V7 的加性分解作为"条件归纳偏置"保留。

---

## 0. 一句话结论

V7 的加性分解（`y = μ + rig + act`）作为**条件归纳偏置**是对的，但它的**输出表示、rig 编码器、通道处理、评测、数据方案**都太"通用"了。V2 给出的 Live2D 专用架构（参数即 Token / 扫掠探针指纹 / 三路分诊 / 排除表）有 AnyTop、URMA 等多方独立文献背书，必须吸收。下面按"保留 / 修正 / 新增"三类列出。

---

## 1. 最关键的修正：输出表示从"固定 20 通道"改为"参数即 Token"

**V7 原设**：输出空间 = 20 通道 CANON 曲线（V7 §2/§4）。
**问题**：CANON-20 是我们在 V4–V6 里用的**分析/特征空间**，不是部署输出。Live2D 各模型参数命名/数量完全不一致（V2 §3.1），固定维动作头在跨本体上被 URMA 实测为**显著最差**。

**修正（V2 §3.1–3.2，四方独立证据 AnyTop/URMA/CrossFormer/MERL）**：
- 生成输出 = **每自由度一个 token，共享输出头**（token 集合 > 多头 > padding）。
- 每个参数 `p` 有**四路身份嵌入** `e_p = MLP(concat[E_text(多语言名), E_probe(扫掠指纹), E_num(量程), E_topo(Deformer树)])`，加到该参数所有帧 token 上。
- 训练时对 `E_text` 做 **10–30% dropout**（SAME 式），强迫模型在 `Param14` 无名参数时靠探针+量程+拓扑推断身份。

**与 V7 加性分解的桥接**：CANON-20 通道是**语义锚点**；每个目标模型参数经身份嵌入关联到某个 CANON 概念（"左眼开"↔CANON 面部通道）。分解从"输出相加"重新定位为**条件归纳偏置**：生成条件 = rig 嵌入（探针/静态，角色级）+ 动作嵌入（文本+B1示例，CANON 对齐）+ 全局均值。DiT 用 per-param token 解码出实际模型参数。**两者互补，不矛盾。**

---

## 2. Rig 编码器大幅升级：从"参数集 Jaccard + mobility"到 V2 扫掠探针指纹

**V7/V6.2 的 rig 输入**：参数集存在性 + mobility（幅度 std）——信息量有限。
**V2 §3.3 的探针**：用 Cubism Core `csmGetDrawableVertexPositions`，**纯 CPU、秒级、无需渲染**，得精确形变场，提取指纹：
- 空间（受影响 Drawable 集合/占比、位移质心、包围盒、PCA 主方向）
- 幅度（最大/平均位移，按角色高度归一）
- 类型（平移/旋转/缩放/局部非刚性，仿射拟合残差）
- 非线性度（Δ 随 v 的曲率）、不透明度变化

这比 mobility 信息量大一个量级，是**零样本上新模型**的关键，也直接对应 V6.2 想测却没数据支撑的"探针"。

**更关键的洞察（V2 §2.3/§1）**：**生成好 6 个 root 通道（ParamAngleX/Y/Z、ParamBodyAngleX/Y/Z），物理系统（physics3.json）会免费送几十个通道的高质量次级运动**——头发/衣物动态全由这 6 个输入驱动。
→ 这**重新框定 V6 的"rig 瓶颈"**：物理驱动通道的 rig 在 `physics3.json` 的 Input→Output 图里已知，不该由模型学。V6 测的"36%/53% rig 恢复"可能有一部分是把这些已知物理通道当成了生成目标。
→ **提议实验**：用 V2 排除表重跑 V6 rig 分析（剔除 physics-output 通道），看 rig 瓶颈是否显著缩小——这是一个能直接修正我们之前结论的具体验证。

---

## 3. 通道三路分诊（V2 §4）取代"20 通道 + 常量 passthrough"

V7 笼统说"输出 20 通道 + 常量 passthrough"，漏掉了 Live2D 最致命的**极端异构通道统计**问题。改为：

| 类别 | 典型成员 | 处理 |
|---|---|---|
| **连续 continuous** | Angle*/BodyAngle*/EyeBall/Brow/MouthForm/Breath + 手臂通道 | flow matching 主通道 |
| **事件 event** | EyeLOpen/ROpen（若不排除）、表情瞬切、PartOpacity 显隐 | 点过程 + 模板核，**不进高斯扩散** |
| **静态 static** | 服装、配饰、罕用变形 | **不生成**，冻结在 default |

**三张排除表（V2 §2.3）在数据清洗阶段就执行，不是生成阶段**：
1. `physics3.json` 的 Output 参数（写了也会被物理覆盖，纯训练噪声）
2. `Groups.LipSync`（交给 MotionSync SDK）
3. `Groups.EyeBlink`（交给 SDK 自动眨眼）

**眨眼的正确答案（V2 §4.3）**：默认不生成（SDK 自动，对数正态间隔 3–5s）；仅当指令显式要求（"眨个眼"）时，模型输出**稀疏事件序列 + 模板核**展开，并临时禁用该区间自动眨眼。**这条直接消解了 V6 担心的"均值回归塌陷成半眯眼直线"。**

---

## 4. 稳定 DiT 的具体补丁（V1 §2.3 RDT-1B / GR-3）

V7 只说"轻量扩散 Transformer"，没给稳定性细节。补：
- **QKNorm + RMSNorm 替换 LayerNorm + MLP decoder**（RDT 三件套；V1 明确"去掉会训练爆炸"）。
- **ACI 交替条件注入**（RDT）：图像/文本 token 数量差异大，若每层同注会让图像淹没文本，故相邻层交替注入。
- **多尺度时间注意力**（V2 §3.4）：层间交替窗口 W=16 / W=64，兼顾 3–6 帧眨眼脉冲与 30–90 帧转头；单一窗口会平均掉短脉冲。

---

## 5. 归一化双重下限（V2 §4.4）

V7 用了 q01/q99 但没下限截断。V1/V2 明确这是**必爆坑**（openpi troubleshooting 记录）：近静态通道 σ→0，除法爆炸。
```python
scale_c = max(q99_c - q01_c, 0.05 * (max_c - min_c))   # ★ 用物理量程的 5%，非绝对小数
v_hat   = (v - default_c) / scale_c
```
并额外加一路 `active_mask` 通道告诉模型"这段里这个参数动没动"。

---

## 6. VLM 接口的三处修正

1. **文本编码器必须多语言（mT5 / BGE-M3 / multilingual-E5）**——V7 写"中文句向量编码器"是**错的**：Live2D 大量日式/非标准参数名（`ParamA/I/U/E/O`、`ParamTere`），纯英文/中文编码会在日文名上失效（V2 §2.5）。
2. **KI stop-gradient 显式写入**（V1 §0.3 / V2 §3.5）：动作专家 attend 主干 K/V 时 `sg(·)`，前向照常、反向不回写；加了后 flow 损失权重可直接取 1。
3. **严格 M1→M2 对照（V1 §4.10 / V2 §9）**：先无 VLM 基线（候选 A：多语言文本编码器 + flow DiT）→ FLOWER 中间层融合（候选 C）→ π0+KI（候选 B）。**VLM 增益不可假设**，指令空间不大时纯文本编码器可能就够了。
4. **CFG**：训练时 10–30% 概率丢文本条件（V1 §2.6）；推理 w 网格搜索，配合 `L_bound` 防高 w 过饱和打到边界。

---

## 7. 块间续接 + 自动长度（V7 完全缺失）

- **RTC（arXiv:2506.07339，已进 LeRobot，无需重训）**：新块前缀当 inpainting，加 guidance；`execution_horizon=8~12`、`max_guidance_weight=10.0`、`prefix_attention_schedule=EXP`。对推理延迟鲁棒，比 temporal ensembling 更平滑（V1 §2.6）。
- **自动长度**：Helix 的"任务完成百分比"合成维度（实现简单），或 MotionStreamer 的参考终止潜码 + 距离阈值（V1 §4.7）。

---

## 8. 输出序列化具体化（V7 的"CANNON 解码器"太含糊）

- **v1（先做）**：生成稠密 `T×P` @30fps → **Visvalingam–Whyatt 简化**选关键帧 → **带 Laplacian 正则的闭式 Bézier 拟合** → Segments（V2 §5.1）。
- **⚠️ Meta 计数字段自动校验**：`CurveCount / TotalSegmentCount / TotalPointCount` 必须自动计算一致，写错 SDK 崩溃（V2 §2.1）。这是最容易踩的工程坑。
- **v2（可选）**：关键帧直出（CondMDI mask-concat，直接生成 Bézier 四元组，生成即可落盘，且美术可编辑）（V2 §5.2）。

---

## 9. 评测空间从 CANON-R² 改为渲染/顶点空间（V2 §8）

**参数空间 MSE 跨模型不可比**（维度/语义/量程不同）。V7 的审计 R² 是**研究/分解分析指标**，不是部署验收指标。主指标改为：
- **顶点空间**（最精确、无需渲染）：`csmGetDrawableVertexPositions` 逐帧 L2，按角色高度归一。
- **渲染空间**：逐帧 LPIPS / DINOv2 特征距离 / FVD。
- **事件级**（总 MSE 对其完全失明）：眨眼次数/分钟、间隔分布 KL、峰值幅度分布。
- **物理合法性**：参数越界率、**physics-exclusion 泄漏率**（写了不该写的参数）。
- **多样性**：同指令多次采样 inter-diversity（防 flow 模态坍塌）。

---

## 10. 数据引擎（V2 §6）取代模糊的 FOCUS 清单

V7 §5.4 的"按 FOCUS 动作清单均衡采样 + 扩语料"太笼统。V2 §6 给出可执行的五路数据引擎，且**直接解决 V5 的"数据少/角色优先"问题**：
1. **探针库**（每模型一次性）→ 参数身份证，是一切前提。
2. **真实 motion3.json** → 金标准，干净带手工 motion 的只有几十个模型。
3. **程序化 + 渲染 + VLM 反向标注** → 无限量合成 `(text, video, params, model_id)` 四元组。
4. **跨模型重定向增强** → 一条 motion 经探针指纹语义对齐重定向到 N 个模型，**免费 10× 数据**，且直接实现 V5 想要的"每动作 ≥8 角色均衡"。
5. **面捕弱监督** → 量大但只覆盖面部、风格偏，**只做预训练，不主训**。

**inverse model（video→params）用有限差分雅可比 + Gauss-Newton**（V2 §6.3）：因为 Cubism Core 正向模型精确已知，**不需要可微渲染器**——`J[:,p] = (V(θ+δe_p) − V(θ−δe_p))/(2δ)`，P=100 时亚毫秒。同域（渲染的 Live2D 视频）几乎完美反解，跨域（真人/动画）先提 2D landmark 再软匹配。

---

## 11. Few-shot 分级（L0/L1/L2/L3）映射 B1→A

V7 把零素材/有素材做成 A/B1 二元。V2 §7 给出更细、更平滑的升级阶梯：
- **L0 零样本（5 分钟，无训练）** = 我们的 **B1 路径**（探针 + 排除表 + 拓扑 → 直接生成）。
- **L1 参数嵌入残差反演（几十步，几分钟）** = "目标补少量片段"：只训 `Δe_p`（textual inversion），冻结主干，参数量 `P×F≈5万`，**对应 V7 的 A 路径入口**。
- **L2 LoRA**（rank 8–16，几十条数据）；**L3 PCA 头**（UniTalker 式，头部高频角色精修，失零样本，仅作补丁）。
→ 比 V7 二元更细，且给出"从零样本到自有片段"的平滑升级与兜底（强 OOD 用 L1 反演）。

## 12. 与 V7 一致、可保留的部分

- flow matching + `Beta(1.5,1)` 时间步 + 4–10 步 Euler ✓（V1 §0.2/§2.6，V2 §3.5）
- 加性分解作为**条件归纳偏置**（重新定位，非输出相加）✓
- **B1 检索（已产品化 `deploy/rig_retrieval/`）作为示例条件来源** ✓
- 静态 moc3 / 探针 rig 恢复（概念保留，rig 输入升级为 V2 丰富探针）✓
- 多模态必须用 flow 而非 L1（动画同一指令对应多种合理动作，L1 会出"平均僵硬"）✓（V1 §2.5）

## 13. 落地优先级重排（取代 V7 的 P0–P5）

| 阶段 | 内容 | 与 V7 的差异 |
|---|---|---|
| **P0（真 P0）** | 渲染 + 扫掠探针管线（M0）+ motion3 读写 + 三张排除表 + Meta 校验 | V7 的"编解码器+物理拆分"只是其中一小块；**渲染/探针管线才是真瓶颈** |
| **P1** | 单模型稠密帧 flow 基线（**无 VLM，候选 A**） | 验证"扩散能否学 Live2D 曲线"这一最核心假设，再往下走 |
| **P2** | 参数即 Token + 四路嵌入 + 拓扑注意力偏置 + 跨模型零样本 | 核心创新；必须做 token vs 多头 vs padding 对照 |
| **P3** | 通道三路分诊 + 稳定 DiT 补丁（QKNorm/RMSNorm/MLP-dec）+ 多尺度时间窗 + RTC | 解决异构通道与块间跳变 |
| **P4** | VLM（严格 M1→M2 对照）+ 数据飞轮（inverse model + 跨模型重定向） | VLM 非必需，按对照决定 |

## 14. 两个必须马上做的验证实验（修正我们之前的结论）

1. **用排除表重跑 V6 rig 分析**：剔除 physics-output / LipSync / EyeBlink 通道后，看"rig 瓶颈 36%/53%"是否显著缩小——若缩小，说明 V6 高估了需学习的 rig，物理通道的 rig 本就在 physics3.json。
2. **CANON-20 vs per-param-token 在同一批模型上对照**：确认 per-param-token 在跨模型零样本上确实优于固定维（URMA 证据需在我们的数据上复现）。
