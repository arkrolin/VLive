# Live2D 动作生成 方案 V4
## 跨角色可迁移性实测 与 架构修正

> 触发：需求边界被明确为「**语料中不存在该角色的该动作**」，检索+retarget 出局。
> 本文所有数字均来自 leave-one-CHARACTER-out 协议，可用 `tools/` 下脚本复现。

## 2. 方法修正：轨迹检索是错误的探针

r@1 要求两位不同画师的曲线**逐点对齐**。生成模型不需要这个——它需要的是
「哪些通道动、动多大、什么节奏」。把可迁移性拆成 4 层重测。

**协议**：leave-one-character-out，加性分解

```
f(char, action) ≈ mu + rig(char, 该角色的其他动作) + λ · act(action, 其他角色)
```

- `rig` 项只用目标角色的**其他动作** —— 正是部署时能拿到的 few-shot
- `act` 项只用**其他角色** —— 正是跨角色共享先验
- λ 必须扫描：跨角色估计的项**方向对但尺度错**

### 结果

| 层级 | 只有 rig few-shot | + 跨角色动作先验 | 最优 λ |
|---|---|---|---|
| **L1 通道是否真的动** (20d) | R²=0.143 | **R²=0.317** (+20.2%) | 0.75 |
| **L2 振幅签名** (20d) | R²=0.310 | **R²=0.411** (+14.7%) | 0.50 |
| L3 节奏包络 (47d) | ≈0 | +4.3% | 0.50 |
| **L4 完整轨迹** (960d) | +0.004 | **+0.5%（死）** | 0.20 |

**结论：共享先验在粗规划层是真实的（+15%~+20%），在轨迹层是零。**

### 两个不修就会得出相反结论的坑

1. **λ 硬写成 1.0** 时，动作先验显示 −10%~−12%（看似有害）。扫描后 0.5~0.75 是 +15%~+20%。
2. **「通道激活」不能用「曲线是否存在于文件里」**。Cubism 导出器会写入全部已绑定参数，
   那测的是导出器习惯（rig 属性），不是编舞。改用 `amp > 0.15 × 该通道语料中位振幅` 后，
   L1 从「零信息」变成增益最大的一层。

## 3. 核心发现：可迁移的是手势语素，不是情绪语素

89 个动作（≥4 角色）按跨角色一致性排序后，榜首与榜尾泾渭分明：

- **榜首**：`motoubiyan` `motouweixiao` `motouxiao` `motouhaixiu` `tuoyehaixiu` `tuoyeganga`
  —— 前缀 `motou`(摸头) / `tuoye`(托腮) **描述手的物理位置**
- **榜尾**：`weixiao`(微笑) `jingya`(惊讶) `sikao`(思考) `xiunu` —— **纯情绪**

| 类别 | n | 一致性均值 | 中位 |
|---|---|---|---|
| 含手势语素 | 20 | **+0.633** | +0.622 |
| 无手势语素 | 64 | +0.217 | +0.222 |

### 同情绪配对对照（排除「复合词天然更具体」的混淆）

同一个情绪词，只看加不加手势前缀：

| 情绪裸词 | 一致性 | 加手势前缀 | delta |
|---|---|---|---|
| weixiao 微笑 | +0.012 | motouweixiao **+0.96** | **+0.946** |
| wushi 无视 | +0.073 | motouwushi +0.78 | +0.707 |
| yihuo 疑惑 | +0.037 | tuoyeyihuo +0.71 | +0.516 |
| ganga 尴尬 | +0.364 | tuoyeganga +0.86 | +0.497 |
| haixiu 害羞 | +0.449 | motouhaixiu +0.88 | +0.426 |
| huangzhang 慌张 | +0.546 | tuoyehuangzhang +0.75 | +0.201 |

**6/6 全为正，平均 delta +0.55。**

> **语料能教会「手放到头上」，教不会「微笑」。**
> 文本条件必须是**手势/姿态规格**，不能是情绪标签。

这条对项目是好消息：这个分解恰好是 LLM 最擅长的事，**零训练数据成本**。

## 4. 逐通道：手臂「动不动」可迁移，「动多大」不可迁移

| 通道 | L2 振幅·动作增益 | L1 激活·动作增益 |
|---|---|---|
| eye_l / brow_l / head_x | +29.5% / +23.9% / +22.4% | +40.0% / +38.0% / +27.0% |
| **arm_r_1** | **−0.5%** | **+16.4%** |
| **arm_l_1** | **−1.0%** | +10.7% |
| hand_r_1 / hand_l_1 | +6.7% / +6.0% | +10.8% / +7.1% |
| arm_l_2 / arm_r_2 | +7.7% / +6.4% | −1.9% / −8.3% |

手臂振幅的 `R²_rig` 已达 **0.52~0.60**，但那主要是 **rig 的参数量纲**
（有的 rig 手臂参数是 0~1，有的是 −30~30），不是编舞信息。
去掉 rig 项后，动作标签对手臂振幅的贡献**归零**。

> **架构含义：手臂动不动由文本决定；动多大必须由该 rig 的 few-shot 统计决定。**

这反而是好事——手臂量纲本来就该从 rig 里读，不该由文本编码。

## 5. 上界：生成模型要补多大的缺口

| 条件 | L2 振幅 R² | L1 激活 R² |
|---|---|---|
| 只有 rig few-shot | +0.327 | +0.141 |
| **+ 跨角色动作先验（可部署）** | **+0.438** | **+0.309** |
| 同角色旧版本（oracle = retarget，已出局）| +0.690 | +0.533 |

**缺口 ≈ 0.22~0.25 R²** —— 这是生成模型必须自己发明、语料给不了的部分。

补充警示：跨角色识别（仅用先验）top1=10.5% vs chance 4.0%（2.6x），
而**单独一维时长就有 6.5%（1.6x）**。也就是说相当一部分「语义」其实只是动作时长。
不要把 2.6x 当成很强的信号。

## 6. 修正后的三层架构

```
自然语言指令
      │
      ▼
┌─────────────────────────────────────────────┐
│ A 层  LLM 分解（零训练）                      │
│   "害羞地打招呼"                              │
│    → 右手抬至头侧 / 头部左倾 15° / 眼半闭      │
│    → 时长 3~4s / 起收各 0.5s                  │
└─────────────────────────────────────────────┘
      │  结构化手势规格（不是情绪标签）
      ▼
┌─────────────────────────────────────────────┐
│ B 层  粗规划（跨角色可学，语料支持 R²≈0.44）   │
│   激活通道掩码 + 相对振幅 + 时长 + 节奏骨架    │
│   训练集：3668 资产 / 130 动作 / 35 角色       │
│   切分必须按 CHARACTER                        │
└─────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────┐
│ C 层  逐 rig few-shot 生成（跨角色信号≈0）     │
│   粗规划 + 该 rig 的既有动作 → 实际曲线        │
│   手臂量纲、缓动风格、物理留给播放器           │
└─────────────────────────────────────────────┘
      │
      ▼  .motion3.json
```

**明确不做的事：大规模 text→trajectory 预训练。** L4 跨角色增益 +0.5%，投入产出不成立。

## 8. 需要你决策的两点

### 8.1 参考视频能否描述「目标动作」？

目前设定：参考视频 = 同角色已有的 Live2D 动画，用来理解图层 → 这只提供 **rig 信息**，
不提供**编舞信息**。而 §5 说明编舞正是语料补不上的那 0.25 R²。

如果允许参考视频（或第二路输入）是**目标动作本身的任意来源**——真人视频、
其他角色的动画、甚至手机随手拍——问题就从「凭文本发明编舞」（语料教不了）
变成「把编舞 retarget 到新 rig」（可解，且不违反"不需要人工二次编辑"）。

这是目前**投入产出比最高的一个设计开关**。

### 8.2 手势词表要不要人工定义？

§3 说明可迁移的是手势语素。语料里的手势语素是**自然涌现**的
（`motou`/`tuoye`/`xianqunzi`/`baoxiong`...），数量有限。

- **方案 A**：从 3668 个资产的文件名里自动挖掘手势语素，建立 20~40 词的受控词表，
  LLM 负责把自由文本映射进去。成本低，覆盖受限。
- **方案 B**：人工定义一套身体部位×目标位置的组合式规格（右手×头侧/脸颊/胸前/腰...），
  再用少量标注把语料对齐进去。成本高，可组合泛化。

我倾向 A 先跑通，因为它今晚就能出结果，而且能直接量出词表覆盖率再决定要不要上 B。
